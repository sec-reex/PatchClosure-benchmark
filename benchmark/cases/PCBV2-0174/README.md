# plexus-archiver-symlink-extraction-bypass

不完整修复分析见 [INCOMPLETE_FIX_ANALYSIS.md](INCOMPLETE_FIX_ANALYSIS.md)。

Gold CVE->CVE incomplete-fix pair (Variant A, faithful-core, REAL-APP-HTTP, real Docker gate PASSED).
A REAL Java HTTP service extracts an **externally-uploaded** tar archive with the real Plexus Archiver
(the classic Zip-Slip upload surface); the extraction is triggered by an **external HTTP archive upload**.

- **CVE-2018-1002200** (ZipSlip: an uploaded archive entry named `../...` is written outside the extraction
  dir) -- fixed in **plexus-archiver 3.6.0** by a canonical-path containment check in
  `AbstractUnArchiver.extractFile`.
- **CVE-2023-37460** (INCOMPLETE fix): a **dangling symlink** entry plus a same-name regular-file entry
  bypasses that check -- `getCanonicalPath()` on a dangling symlink returns the link's own source (passes
  containment), then the write follows the symlink outside the dir. Fixed in **4.8.0** by an added
  `Files.isSymbolicLink` guard. CWE-22 / CWE-61.

## Service (real external HTTP trigger)
`com.pcb.ExtractHttpService` (JDK built-in `com.sun.net.httpserver.HttpServer`):
- `POST /extract` -- raw request body = the uploaded `.tar`. The service writes it to a temp file, then
  `TarUnArchiver ua = new TarUnArchiver(); ua.setSourceFile(uploaded); ua.setDestDirectory(/work/dest);
  ua.extract();` (the REAL, unmodified Plexus extraction path). After extraction it checks the escape
  witness `/work/out/flag` (OUTSIDE dest) and returns its content.
- `GET /health` -- readiness.
